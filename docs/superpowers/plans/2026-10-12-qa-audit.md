# QA Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the whole site works end-to-end — catalogue-driven content integrity, automated user flows, cross-view visual fidelity against agency-design-v2, and WCAG-AA accessibility — as five independently shippable QA sprints.

**Architecture:** Tests only, no product code changes expected. Each sprint adds Playwright specs (data-driven fixtures derived from `content/{en,fr}` via a shared loader, mirroring `src/schemas/service.ts` types so a valid catalogue always satisfies the assertions) and validation scripts that run inside the existing `pnpm gate`. Console/network/pageerror assertions use one Playwright fixture (`test.use({ ... })` + `page.on`) so noise rules live in a single helper.

**Tech Stack:** Playwright 1.63 (already in devDependencies), Vitest, `@axe-core/playwright` (one new devDependency — ask before adding), existing `scripts/gate.mjs` pipeline. No Percy/Chromatic — plain `toHaveScreenshot` with deterministic viewport sizes.

**Spec:** the chat spec of 2026-10-12 ("Data integrity … Accessibility"), reproduced in full in each sprint's objective. The plan implements its Phase 1 (functional/data), Phase 2 (visual) and accessibility parts.

## Global Constraints

- Package manager is pnpm; tools are invoked as `node_modules/.bin/<tool>` on Windows.
- No new runtime dependencies; `@axe-core/playwright` needs a yes before install.
- Prices and durations come from the shared helpers, never literals — QA tests must *derive* expectations from `content/{en,fr}` and `src/seo/price.ts`, not re-type amounts.
- All tests must be hermetic: seed no network beyond `http://localhost:3000`; `wa.me` external links are asserted as hrefs, never followed.
- `playwright.config.ts` starts its own server on :3000 after `next build`; never run a second server for e2e.
- Test files live in `tests/e2e/qa/**` and helpers in `tests/e2e/qa/helpers/`; keep existing suites untouched.
- One `HIGH`/`MED`/`LOW` severity per finding; defects get a `reports/qa-*.md` entry, not silent fixes.

## Review Focus

Accounts for the five ways this site will hurt a real visitor that no task's test exercises spec-silently:

1. **Empty/missing optional content fields** (`itinerary`, `capacity`, `routes`, `bring`, `restrictions`, `nightSurcharge`) — expect: tile/section/accordion absent, never a bare `undefined` or 1px-tile clip; **test:** `data-integrity.spec.ts` iterates every service × both locales asserting no `/undefined|,\s*,|>  €/` appears.
2. **Very long titles and FR long words** (e.g. `Excursions d'une journée au départ d'Agadir`) — expect: no horizontal scroll and no clipped descenders at 320px; **test:** `visual.spec.ts` width-sweeps `320/375/768/1024/1440/1920` asserting `document.scrollWidth <= clientWidth` per page.
3. **Old URLs from the two `.txt` source catalogues** (slug spellings the design may have renamed) — expect: old path 301/308-redirects to the new one, or the sitemap URL 200s; **test:** `regression.spec.ts` hits every source-catalogue slug via both the path and the sitemap and reconciles with proxy.ts redirects.
4. **Currency formatting consistency MAD/EUR** — expect: the same service never shows mixed currency on one page (card vs JSON-LD vs estimate); **test:** `data-integrity.spec.ts` extracts every `€|MAD|dirham` token per page and asserts a single currency per page (EUR site-wide, per `data/source` §3).
5. **Double-click / double submit on the booking form** — expect: exactly one inquiry row per click pair (the server action dedupes via `InquiryState.attempt`); **test:** `flows.spec.ts` double-clicks submit on a valid form and asserts one success panel, zero console errors.
