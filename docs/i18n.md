# Internationalization

## Locales

`LOCALES = ["en", "fr"]` with `DEFAULT_LOCALE = "en"` in `src/i18n/locales.ts`.
`isAppLocale(value)` is the type guard used by layouts and pages (instead of
`locale as any`). `isRtlLocale` exists for the future Arabic locale and currently
only matches `"ar"`.

## Messages

UI copy lives in `messages/{en,fr}.json`, grouped by namespace: `nav`, `footer`,
`common`, `home`, `hubs`, `hub`, `product`, `book`, `notFound`. It is loaded by
`src/i18n/request.ts` and read in server components with
`getTranslations({ locale, namespace })` and in client components with
`useTranslations`.

**Add the key to both locales.** Do not hardcode user-visible strings in
components. Per-service copy is different: it lives in `content/{en,fr}`.

## Routing

`src/i18n/routing.ts` defines the locale prefix (`always`), disables automatic
detection, and declares typed `pathnames`:

```
"/", "/excursions", "/activities", "/transfers", "/book", "/[slug]"
```

`createNavigation` exports the locale-aware `Link`, `redirect`, `usePathname`,
`useRouter` and `getPathname`. Use the typed `Link`: static routes as strings
(`href="/excursions"`) and the product route as an object
(`href={{ pathname: "/[slug]", params: { slug } }}`).

`src/proxy.ts` (next-intl) applies the locale prefix before routes render.

## Static rendering

Because pages use request-scoped translation, call `setRequestLocale(locale)` at
the top of each page/layout/hub route to keep them **statically generated**. The
layout also wraps the tree in `NextIntlClientProvider` so client components can
translate and use locale-aware navigation.

## The locale switcher

`src/components/locale-switcher.tsx` is a client component that keeps the visitor
on the **same page** when switching language. It resolves the counterpart
service slug from the map the layout injects (`getSlugAlternates()`). Hub slugs
are identical across locales; product slugs differ and must be translated.

## RTL

Layout uses CSS logical properties throughout, so an `ar` locale mainly needs:
adding `ar` to `LOCALES`, `messages/ar.json`, an Arabic-capable font, and content.
The layout already sets `dir` from `isRtlLocale`.
