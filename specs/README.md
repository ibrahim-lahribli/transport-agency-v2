# Specifications

Specs are the shared source of truth for a piece of work. They are living
artifacts: write them before code, refine them as you learn, and keep them short.

## Gated workflow

1. **Specify** — describe the *what* and *why*: users, journeys, success. No
   stack yet. Use [TEMPLATE.md](TEMPLATE.md).
2. **Plan** — the technical shape: stack, data model, constraints, risks.
3. **Tasks** — break the plan into small, independently testable chunks.
4. **Implement** — build one task at a time, verifying before moving on.

Do not start the next phase until the current one is clear. Keep a spec to 1–3
pages; split it if it grows. Always include an explicit **out of scope** section.
